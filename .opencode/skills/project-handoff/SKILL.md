# Восстановление и передача контекста

## На старте
1. Прочитай AGENTS.md, docs/STATE.md, docs/HANDOFF.md, docs/PLAN.md и релевантные решения в docs/DECISIONS.md.
2. Сверь записи с файловой системой, Git status/diff и текущей задачей. Git проверяй только если репозиторий существует; отсутствие Git отметь, не инициализируй без согласования.
3. Сохрани чужие незакоммиченные изменения. Не считай незнакомый diff своей работой.
4. При конфликте документов с кодом сообщи расхождение. Не стирай решение пользователя на основе предположения.
5. Назови одну ближайшую задачу и критерии её завершения.

## Контрольная точка
Обновляй после законченной задачи, значимого сбоя и по запросу «сохрани контекст».
- STATE.md: реализованное, текущая задача, блокеры, фактические проверки.
- HANDOFF.md: где остановились, изменённые файлы и причина, результаты, следующая конкретная команда/операция, риски.
- PLAN.md: отмечай только этапы с выполненными критериями приёмки.
- DECISIONS.md: добавляй только существенные решения; отличай предложенное от принятого.

Для каждой проверки сохраняй команду, результат, краткую причину ошибки. Отмечай «не запускалось» вместо выдуманного успеха. Большие логи не копируй: достаточно первопричины и способа воспроизведения.

## Ограничения
Не обещай автоматическое сохранение при аварийном закрытии. Не сохраняй полную историю беседы, внутренние рассуждения, секреты и личные данные. Не создавай commit/push ради checkpoint без согласия.
Держи STATE.md и HANDOFF.md краткими, ориентир до 100 строк на файл. Не дописывай бесконечный дневник в текущий статус.

## Завершение
Перечисли изменённые документы и следующий шаг. Если запись запрещена, выдай черновик контрольной точки в чат и явно скажи, что файлы не сохранены.
