# Ручная проверка M3 (STT / Whisper)

Гайд для владельца проекта: как вручную проверить голосовой ввод (whisper.cpp) на
эмуляторе и реальном телефоне. Документ описывает только то, что уже реализовано и
собрано в текущем состоянии ветки. Он не меняет код, сборку, модели и состояние
устройств.

- Язык интерфейса, сообщений об ошибке и отчёта — русский.
- Названия типов, API, полей и файлов — как в исходнике (латиницей).
- Все пути относительны к корню проекта.

## 1. Что проверяем, а что — нет (границы)

Проверяем (M3, голос):

- Запись речи с микрофона (16 кГц моно, лимит 60 с, автофоллбек на 48 / 44,1 кГц).
- Транскрипцию локально на устройстве (whisper.cpp, офлайн, без сети).
- Вставку распознанного текста в редактируемый черновик **без автоотправки**.
- Отмену записи, черновик при уходе в фон, отмену распознавания.
- Скачивание / импорт / удаление модели распознавания через UI.
- Явную отправку собранного вручную черновика в Qwen (кнопкой, не автоматически).

Не проверяем этим гайдом:

- Количественную точность распознавания (WER/CER) на заданном наборе фраз — см. §10.
- Календарь, RAG, embedding-модели (не реализованы).
- Качество ответов Qwen по сути (это M2).
- Release-сборку, R8, нагрев, долгую сессию (это отчёт §9, не M3).

## 2. Порядок проверок

Выполняйте сверху вниз. Каждая карточка — отдельное состояние, результат фиксируется
в шаблоне (§11). Если шаг упал в ошибку — зафиксируйте её в §11, не переходите дальше,
пока не восстановите рабочее состояние.

Порядок:

1. A — Подготовка (сборка, установка, устройство).
2. B — Разрешение на микрофон.
3. C — Подготовка модели распознавания (скачивание или импорт).
4. D — Запись и распознавание (основной сценарий).
5. E — Вставка в черновик (проверка «без автоотправки»).
6. F — Явная отправка черновика в Qwen.
7. G — Отмена записи.
8. H — Черновик при уходе в фон (stop-and-hold).
9. I — Отмена распознавания.
10. J — Голосовые ошибки и крайние случаи.
11. K — Замена / удаление модели распознавания.
12. L — Тестовый набор русской речи (качественная оценка).
13. M — Замеры (время, размеры).
14. N — Диагностика (логи).

## 3. Подготовка и сохранение данных

### 3.1 Что нужно до начала

- Проект в текущем состоянии (M3 собран). Не переключайте ветки во время проверки.
- Доступ к сети **только** для шага C, если выбираете скачивание. Остальные шаги —
  офлайн: перед записью можно включить авиарежим, распознавание не пострадает.
- Файл модели распознавания (если выбираете импорт): `ggml-base.bin`,
  ровно `147 951 465` байт, SHA-256
  `60ed5bc3dd14eea856493d334349b405782ddcaf0028d4b5df4088345fba2efe` (см. §4.4).
- Модель Qwen для чата уже готова (M2), иначе карточка F невыполнима.

### 3.2 Как сохранить существующее состояние приложения

Перед тем как менять модели или данные:

1. Откройте приложение, убедитесь, что история чата на месте (она сохраняется на диск).
2. Сделайте снимок экрана чата — это точка отката «что было до проверки».
3. Если планируете удалять / заменять модель распознавания (K), имейте под рукой
   второй вариант получения модели (скачать или импортировать заново), чтобы не
   остаться без STT.
4. Не добавляйте в репозиторий `local.properties`, `*.gguf`, аудио — они не должны
   попадать в коммит (в `.gitignore`: `models/`, `*.gguf.part`).

> Важно: изменение модели распознавания (K) не влияет на модель Qwen и на историю
> чата. Данные чата хранятся отдельно и от STT не зависят.

## 4. Эмулятор и телефон: минимальная подготовка

### 4.1 Эмулятор (проверка уже проходила на `emulator-5554`)

- x86_64, API 37, 6 ГБ RAM, 6 потоков, `n_ctx=2048`.
- Микрофон эмулятора использует микрофон хоста. Для проверки речи говорите в
  микрофон хоста (или подайте звук), а не в экран.
- Сборка: `.\gradlew.bat :app:assembleDebug`.
- Установка: `adb install -r app\build\outputs\apk\debug\app-debug.apk`.
- Логи: `adb logcat -s AudioRecorder WhisperRepository AsrEngine`.

### 4.2 Реальный телефон (arm64)

- Минимальные требования: Android 8.0+ (minSdk 26), ARM64, 4 ГБ RAM (рекомендую 6+),
  ~500 МБ свободного места (модель ~148 МБ + резидентные ~400 МБ при распознавании).
- Проверьте, что устройство видит микрофон: откройте системные настройки микрофона /
  приложение-диктофон и запишите тестовую фразу.
- Сборка и установка те же, что в 4.1. Логи: `adb logcat -s AudioRecorder WhisperRepository AsrEngine`.
- Если телефон не arm64 или RAM меньше 4 ГБ — распознавание может не загрузиться;
  зафиксируйте это как ограничение, а не дефект.

### 4.3 Модель распознавания — откуда взять

| Способ | Что делать | Когда выбрать |
|---|---|---|
| Скачивание в приложении | Карточка C, путь «Скачать» | Есть стабильная сеть; ~141 МБ, SHA-256 проверяется автоматически |
| Импорт через SAF | Карточка C, путь «Импорт» | Нет сети на устройстве; файл `ggml-base.bin` заранее в «Загрузки» |
| adb push + run-as | См. 4.4 | Быстрый способ для повторных прогонов, без UI |

### 4.4 Быстрая установка модели через adb (повторные прогоны)

```
adb push <путь>\ggml-base.bin /data/local/tmp/ggml-base.bin
adb shell "run-as com.example.localassistant mkdir -p files/whisper"
adb shell "run-as com.example.localassistant cp /data/local/tmp/ggml-base.bin files/whisper/ggml-base.bin"
adb shell "run-as com.example.localassistant sha256sum files/whisper/ggml-base.bin"
```

Ожидаемый SHA-256: `60ed5bc3dd14eea856493d334349b405782ddcaf0028d4b5df4088345fba2efe`.
После этого в карточке C панель должна показать «Модель готова».

## 5. Карта состояний и ожидаемый UI

### 5.1 Голосовые состояния (`VoicePhase`)

| Фаза | Что видит пользователь | Кнопки |
|---|---|---|
| `Idle` | Панель голоса не видна; активна иконка микрофона | Микрофон |
| `Recording` | Красная карточка «Запись · M:SS / 1:00», прогресс, подпись «Аудио не сохраняется на диск и никуда не отправляется.» | «Отменить», «Готово» |
| `Draft` | Карточка «Запись остановлена · M:SS», подпись про хранение в памяти | «Удалить», «Распознать» |
| `Transcribing` | Карточка со спиннером «Распознаю на устройстве…» / «Загружаю модель распознавания…» + «Whisper работает офлайн» | «Отменить» |

### 5.2 Состояния модели распознавания (`WhisperModelStatus`)

| Статус | Что показывает панель «Распознавание речи» |
|---|---|
| `Absent` | Описание `Whisper base (multilingual), 141 МБ`, кнопки «Скачать 141 МБ», «Импорт» |
| `Downloading` | Прогресс «Скачивание модели» / «Чтение файла», байты/с, кнопка «Отмена» |
| `Verifying` | Спиннер «Проверка файла…» |
| `Loading` | Спиннер «Загрузка модели в память…» |
| `Ready` | «Модель готова», имя файла, размер, «загружена»/«загрузится при первой записи», кнопки «Заменить .bin», «Удалить» |
| `Error` | Текст ошибки, кнопки «Повторить», «Скачать», «Импорт» |

### 5.3 Кнопка микрофона (`micClick`) — логика нажатия

- Идёт запись → `onVoiceStop()` (завершить запись, начать распознавание).
- Идёт распознавание → нажатие игнорируется.
- Есть черновик (Draft) → нажатие игнорируется (работают «Удалить» / «Распознать»).
- Модель не готова → открывается диалог «Распознавание речи» (`WhisperModelPanel`).
- Модель готова, но нет разрешения → системный запрос на `RECORD_AUDIO`.
- Модель готова и разрешение есть → начинается запись.
## 6. Карточки ручной проверки

Формат каждой карточки: **Цель** → **Шаги** → **Ожидаемо** → **Критерий PASS**.
Результат (PASS / FAIL / NOT TESTED + комментарий) вносится в §11.

---

### A. Подготовка (сборка, установка, устройство)

**Цель:** получить рабочую сборку на целевом устройстве.

**Шаги**
1. `.\gradlew.bat :app:assembleDebug` — сборка успешна, APK в `app\build\outputs\apk\debug\app-debug.apk`.
2. `adb install -r app\build\outputs\apk\debug\app-debug.apk` — установка успешна.
3. Запустить приложение. В шапке — «Локальный ассистент» и подзаголовок состояния модели.

**Ожидаемо**
- Приложение стартует без краша.
- Модель Qwen: либо «Модель готова» (если уже была), либо панель «Модель не установлена».
- Панель «Распознавание речи» видна в диалоге «Модели» (иконка шестерёнки).

**Критерий PASS:** приложение запущено, UI отображается, модель Qwen в состоянии `Ready` (нужно для карточки F).

---

### B. Разрешение на микрофон

**Цель:** получить `RECORD_AUDIO` до первой записи.

**Шаги**
1. Нажмите иконку микрофона при готовой модели распознавания.
2. Если разрешение ещё не дано — появится системный диалог.
3. Выберите «Разрешить».

**Ожидаемо**
- После «Разрешить» запись стартует сразу (см. карточку D).
- При отказе — сниббар «Без доступа к микрофону запись невозможна».
- Если доступ заблокирован навсегда — сниббар «Доступ к микрофону запрещён. Разрешите его в настройках приложения.» с кнопкой «Настройки» (откроет системные настройки приложения).

**Критерий PASS:** разрешение выдано, повторное нажатие на микрофон начинает запись.

---

### C. Подготовка модели распознавания

**Цель:** довести `WhisperModelStatus` до `Ready`.

**Вариант 1 — скачивание (нужна сеть)**
1. Откройте диалог «Распознавание речи» (иконка микрофона при неготовой модели, либо иконка шестерёнки → раздел распознавания).
2. Нажмите «Скачать 141 МБ».
3. Дождитесь окончания: прогресс → «Проверка файла…» → «Модель готова».

**Ожидаемо**
- Прогресс в байтах, скорость в байт/с.
- После скачивания автоматическая проверка SHA-256 (совпало — `Ready`).
- Кнопка «Отмена» прерывает скачивание (возврат к `Absent` или `Error`).

**Вариант 2 — импорт (без сети)**
1. Положите `ggml-base.bin` (147 951 465 байт) в «Загрузки».
2. В диалоге «Распознавание речи» нажмите «Импорт».
3. Выберите файл в проводнике.

**Ожидаемо**
- Копирование с прогрессом.
- Проверки: размер, SHA-256, ggml-магия (`0x67676d6c`).
- Успех → «Модель готова · загрузится при первой записи».
- Невалидный файл → `Error` с текстом: «Ожидается ggml-base.bin (147951465 байт), а выбран файл размером … байт» / «Контрольная сумма файла не совпала с опубликованной» / «Выбранный файл не является моделью whisper.cpp».

**Критерий PASS:** панель показывает «Модель готова» (`Ready`).

---

### D. Запись и распознавание (основной сценарий)

**Цель:** записать речь, получить текст.

**Шаги**
1. Убедитесь, что модель распознавания `Ready`.
2. Нажмите микрофон → старт записи (красная карточка, счётчик `0:00 / 1:00`).
3. Произнесите фразу (см. тестовый набор L), 3–8 с достаточно.
4. Нажмите «Готово».
5. Дождитесь конца распознавания.

**Ожидаемо**
- Фаза `Recording`: прогресс растёт, подпись про приватность.
- После «Готово» → фаза `Transcribing` со спиннером.
- Успех → фаза `Idle`, текст появляется в поле ввода (черновик) — см. E.
- Запись короче 0,3 с → «Слишком короткая запись».
- Нет речи / только шум → «Речь не распознана».
- Ошибка записи (нет микрофона) → «Не удалось записать аудио» (+ причина).
- Ошибка распознавания → «Не удалось распознать речь» (+ причина).

**Критерий PASS:** распознанная фраза появилась в черновике, ошибка не выведена.

**Запись (для §11):** произнесённая фраза, полученный текст, время распознавания.

---

### E. Вставка в черновик (без автоотправки)

**Цель:** убедиться, что текст встаёт в редактор, а НЕ отправляется в Qwen.

**Шаги**
1. Выполните карточку D, доведите до появления текста в поле ввода.
2. Посмотрите на список сообщений сверху.
3. Наберите ещё одно слово вручную в поле.
4. Повторите запись D, добавьте вторую фразу.

**Ожидаемо**
- После распознавания текст добавляется в поле ввода.
- Если поле было пустым — текст встаёт как есть.
- Если в поле уже был текст — новая фраза добавляется **новой строкой** под существующим.
- Сообщение в чате НЕ появляется (автоотправки нет).
- Ручные правки текста в поле сохраняются.

**Критерий PASS:** текст в поле, в чате новых сообщений нет, существующий текст не затёрт.

---

### F. Явная отправка черновика в Qwen

**Цель:** отправить собранный голосом текст в Qwen кнопкой (не автоматически).

**Шаги**
1. В поле ввода должен быть текст (из D/E), модель Qwen `Ready`.
2. Нажмите кнопку «Отправить» (иконка отправки справа от поля).
3. Дождитесь ответа Qwen.

**Ожидаемо**
- Сообщение пользователя появляется в чате с голосовым текстом.
- Qwen стримит ответ.
- Нажатие «Отправить» с пустым полем — ничего не происходит.
- Если модель Qwen не готова — ошибка «Сначала подготовьте модель».

**Критерий PASS:** пользовательское сообщение в чате + стриминговый ответ Qwen, автоотправки не было (проверялось в E).

---

### G. Отмена записи

**Цель:** убедиться, что отменённая запись не влияет на черновик.

**Шаги**
1. Начните запись (микрофон).
2. Произнесите что-нибудь, 2–3 с.
3. Нажмите «Отменить».

**Ожидаемо**
- Фаза возвращается в `Idle`.
- Поле ввода НЕ меняется (черновик не трогается).
- Распознавание НЕ запускается.
- В логах `AudioRecorder` — «Recording cancelled».

**Критерий PASS:** фаза `Idle`, поле ввода без изменений.

---

### H. Черновик при уходе в фон (stop-and-hold)

**Цель:** запись остановлена, распознавание ещё не запущено — черновик сохраняется в памяти, а не теряется.

**Шаги**
1. Начните запись, произнесите фразу.
2. Нажмите микрофон (стоп записи) — фаза станет `Draft`, «Распознать» ещё не нажимали.
3. Уйдите из приложения (кнопка Домой / свитч задач), 10–15 с.
4. Вернитесь.
5. Нажмите «Распознать».

**Ожидаемо**
- При уходе в фон приложение не крашнется, при возвращении фаза остаётся `Draft`.
- После «Распознать» текст появляется в поле ввода.
- Аудио хранится в памяти (не на диске): при уходе в фоне Android может убить процесс — это ожидаемо для `Draft`; если процесс убит, черновик теряется (документируйте).

**Критерий PASS:** возврат из фона не ломает фазию; распознавание запускается из `Draft`.

---

### I. Отмена распознавания

**Цель:** отменить распознавание после нажатия «Распознать».

**Шаги**
1. Доведите до фазы `Transcribing` (после «Готово» или «Распознать»).
2. Сразу нажмите «Отменить».

**Ожидаемо**
- Фаза возвращается в `Idle`.
- Текст в поле НЕ добавляется.
- В логах — «Recognition cancelled».

**Критерий PASS:** отмена отрабатывает, фаза `Idle`, черновик не тронут.

### J. Голосовые ошибки и крайние случаи

| № | Действие | Ожидаемый текст ошибки / поведение |
|---|---|---|
| J1 | Нажать «Готово» через 0,1 с после старта записи | Сниббар «Слишком короткая запись» |
| J2 | Записать тишину 3 с, нажать «Готово» | Сниббар «Речь не распознана» |
| J3 | Убрать микрофон на время записи (эмулятор: отключить виртуальный мик) | Сниббар «Не удалось записать аудио» |
| J4 | Запись 58–60 с | Счётчик доходит до `1:00`, запись автоматически останавливается, фаза `Draft` |
| J5 | Повторить запись сразу после успешного распознавания | Новая запись стартует, поле ввода сохраняет предыдущий текст |
| J6 | Отключить авиарежим/сеть во время распознавания | Распознавание продолжается (офлайн) |

**Критерий PASS:** все 6 строк дают ожидаемое поведение.

---

### K. Замена / удаление модели распознавания

**Цель:** убедиться, что замена и удаление модели работают и не ломают Qwen.

**Шаги**
1. Откройте «Распознавание речи» при `Ready`.
2. Нажмите «Удалить» → подтвердите.
3. Убедитесь: `Absent`, кнопки «Скачать» / «Импорт».
4. Скачайте или импортируйте заново → `Ready`.
5. Нажмите «Заменить .bin» при `Ready` → выберите тот же файл → `Ready`.

**Ожидаемо**
- Удаление: файл удаляется, состояние `Absent`.
- Повторная подготовка: как в карточке C.
- Замена: старый файл заменяется, SHA-256 проверяется, `Ready`.
- История чата и модель Qwen **не затрагиваются**.

**Критерий PASS:** модель можно удалить и восстановить; Qwen и чат не пострадали.

### L. Тестовый набор русской речи (качественная оценка)

Произнесите по одной фразе, фиксируйте распознавание. Набор намеренно простой:
проверяем механику и читаемость, не WER.

| № | Фраза | Что проверяет |
|---|---|---|
| L1 | «Привет, как дела?» | Приветствие, пунктуация, базовая русская речь |
| L2 | «Напиши письмо маме» | Императив, 3 слова |
| L3 | «Сегодня хорошая погода» | Описание, 3 слова |
| L4 | «Мне нужно купить хлеб и молоко» | Список, цифры отсутствуют |
| L5 | «Создай событие на завтра в десять» | Временна́я привязка, цифры словами |
| L6 | «Позвони коллеге Ивану Петрову» | Имена собственные |
| L7 | «Напомни мне про встречу в понедельник» | Глагол «напомни», день недели |
| L8 | «Сколько будет два плюс два?» | Математика, вопрос |

Для каждой: произнести → «Готово» → записать полученный текст → сравнить визуально
(точное совпадение не требуется, важна читаемость).

**Критерий PASS:** ≥ 6 из 8 фраз распознаны читаемо (можно передать смысл без правок).

### N. Диагностика (логи)

**Запуск лога:**
```
adb logcat -c
adb logcat -s AudioRecorder WhisperRepository AsrEngine
```

**Что искать в логах при ошибке:**

| Симптом | Где искать |
|---|---|
| «Не удалось записать аудио» | `AudioRecorder`: причина (код ошибки, доступность мика) |
| «Речь не распознана» | `AsrEngine`: нормальное завершение без сегментов |
| Краш при распознавании | `AsrEngine` + `AndroidRuntime`: stack trace |
| Модель не грузится | `WhisperRepository`: SHA-256 mismatch, размер, ggml-магия |
| Отмена зависла | `AudioRecorder`: «Recording cancelled», `AsrEngine`: «Recognition cancelled» |

**Сохранить лог в §11 при любом FAIL.**

## 8. Частые проблемы и быстрые действия

| Симптом | Быстрое действие |
|---|---|
| «Слишком короткая запись» | Записать ≥ 1 с речи |
| «Речь не распознана» | Произнести громче, ближе к микру; проверить тишину фона |
| Модель не скачивается | Проверить сеть; импортировать файл вручную (4.4) |
| Приложение крашится при распознавании | `adb logcat` → §11; убедиться, что RAM ≥ 4 ГБ |
| Черновик не появляется | Проверить, что фаза была `Transcribing` (не `Draft`); повторить «Распознать» |
| Отправка в Qwen не работает | Убедиться, что модель Qwen `Ready` (карточка A) |
