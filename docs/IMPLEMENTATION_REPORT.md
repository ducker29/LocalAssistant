# Отчёт о реализации: офлайн-чат M2 и STT (whisper.cpp) M3

Дата: 2026-10-24 (M2), 2026-10-25 (M3 / отмена STT). Отчёт фиксирует, что реально проверено,
чем это подтверждено и что ещё не проверено. Все измерения в этом документе получены на
эмуляторе; они не заменяют измерения на телефоне и не являются обещанием производительности
arm64-устройства.

## 1. Что реализовано

- Офлайн-генерация: Qwen3-1.7B Q4_K_M через вендоренный llama.cpp (CPU, без облака).
- Compose-экран чата: история, стриминг, «Стоп», «Новый чат», копирование ответа, ошибки.
- Хранение истории в `filesDir` (JSON, атомарная запись), восстановление после перезапуска.
- Приобретение модели: скачивание с пиннингом размера и SHA-256, импорт GGUF через SAF,
  удаление, повторная загрузка.
- JNI-мост: загрузка/выгрузка модели, генерация с отменой, подсчёт токенов промпта,
  рендер Jinja-шаблона чата.
- Инструментальные замеры в debug-логах: время загрузки, TTFT, скорость декодирования,
  RSS и PSS. Тексты сообщений в логи не попадают — только байты, токены и символы.

## 7. Найденные дефекты и наблюдения (не исправлялись)

1. Список сообщений не прокручивается к новому ответу, когда история длиннее экрана:
   ответ генерируется и сохраняется, но его нужно искать вручную. `LaunchedEffect` с
   `animateScrollToItem` срабатывает не всегда (похоже на конфликт с IME/изменением размера).
2. Убийство процесса во время генерации теряет уже показанный частичный текст: после
   перезапуска ход выглядит как пустое «Остановлено». Статус `INTERRUPTED` корректен,
   но текст не сохраняется, потому что запись выполняется по завершении хода.
3. При готовой модели из UI недоступны «Импорт GGUF» и «Удалить»: в диалоге
   `compact = true` эти кнопки скрыты, а нижняя панель показывается только при
   `status != Ready`. Заменить или удалить рабочую модель через интерфейс нельзя.

Пункты 1–3 не входят в текущую задачу; исправление требует отдельного согласования.

## 8. Методика измерений

- Загрузка: нативный лог `model load took N ms` — от старта `llama_model_load` до готовности
  контекста; `RSS before model load` и `RSS after load` — `VmRSS` из `/proc/self/status`.
- TTFT: `first token after N ms from request` — рендер шаблона, токенизация, декод промпта
  и первый сгенерированный токен; `first visible token after N ms` — момент, когда текст
  попал в UI (разница 3–15 мс).
- Скорость: `decode N ms (X tok/s)`, где `N` — суммарное время декодирования, а токены
  считаются по колбэку (включая первый). Для честного сравнения устройств: 3 прогона
  одинакового промпта, отбрасывая первый (холодные кэши), брать медиану.
- Память: RSS из нативных логов до загрузки, после загрузки, на первом токене и в конце;
  PSS — `adb shell dumpsys meminfo <pid>` во время генерации.
- Сеть: `adb shell svc wifi disable`, `svc data disable`, проверка
  `dumpsys connectivity` и `ping`. После теста — включить обратно.

## 9. Инструкция для проверки на телефоне

Установка APK и любые действия на телефоне выполняются только с разрешения пользователя.

1. Сборка: `.\gradlew.bat :app:assembleDebug`.
2. Установка: `adb install -r app\build\outputs\apk\debug\app-debug.apk`.
3. Модель — любым из способов:
   - скачать в приложении (нужна сеть, ~1,28 ГБ, SHA-256 проверяется автоматически);
   - импорт GGUF через SAF (файл заранее положить в «Загрузки»);
   - `adb push models\Qwen_Qwen3-1.7B-Q4_K_M.gguf.part /data/local/tmp/model.gguf`,
     затем `run-as … cp` в `files/models/model.gguf` и сверка SHA-256.
4. Логи: `adb logcat -s LlmNative LlamaEngine ChatViewModel`.
5. Сценарии по порядку с фиксацией результата:
   - холодный старт → время загрузки и RSS в логах;
   - «Привет» → ответ, TTFT, tok/s;
   - второй вопрос с опорой на первый → проверка контекста;
   - «Стоп» после появления текста → частичный текст + «Остановлено»;
   - новый запрос после отмены → успешный ответ;
   - перезапуск приложения → история на месте;
   - авиарежим → генерация работает;
   - `dumpsys meminfo` во время генерации → PSS;
   - 10–15 минут непрерывной работы → нагрев (`dumpsys thermalservice`), падение скорости.
6. Записать: модель телефона, версию Android, объём RAM, число потоков, `n_ctx`,
   медианы TTFT и tok/s, PSS в покое и при генерации, замеченные дефекты.

## 11. M3: STT через whisper.cpp — отмена транскрипции

Дата: 2026-10-25. Все измерения на `emulator-5554` (x86_64, API 37, 6 потоков, 6 ГБ RAM).

### 11.1. Что реализовано

- Модуль `:whisper` — NDK-сборка вендоренного whisper.cpp; JNI-мост `whisper_jni.cpp`
  с поддержкой отмены через `AtomicBoolean` и `abort_callback`.
- Тест `WhisperCancellationTest` — проверка, что отмена возвращает `null` и тот же
  движок может транскрибировать повторно.
- Исправлен дефект задержки отмены: убран 8x-троттлинг проверки флага в
  `abort_callback` (см. §11.2).

### 11.2. Точное изменение в `abort_callback`

**Было (с троттлингом):**

```c
bool abort_callback(void * user_data) {
    auto * context = static_cast<AbortContext *>(user_data);
    if (context == nullptr || context->env == nullptr || context->flag == nullptr) {
        return false;
    }
    if ((++context->counter & 7) != 0) {
        return context->cancelled;
    }
    context->cancelled = context->env->CallBooleanMethod(context->flag, context->get) == JNI_TRUE;
    if (context->cancelled && !context->observed) {
        context->observed = true;
        LOGI("DIAG abort observed by native callback counter=%d", context->counter);
    }
    return context->cancelled;
}
```

**Стало (без троттлинга):**

```c
bool abort_callback(void * user_data) {
    auto * context = static_cast<AbortContext *>(user_data);
    if (context == nullptr || context->env == nullptr || context->flag == nullptr) {
        return false;
    }
    context->cancelled = context->env->CallBooleanMethod(context->flag, context->get) == JNI_TRUE;
    if (context->cancelled && !context->observed) {
        context->observed = true;
        LOGI("DIAG abort observed by native callback invocation=%d", context->invocations);
    }
    ++context->invocations;
    return context->cancelled;
}
```

Изменения:
1. Убрана проверка `if ((++context->counter & 7) != 0) { return context->cancelled; }` —
   флаг `AtomicBoolean` теперь читается при **каждом** вызове callback, а не каждый 8-й.
2. Переменная `counter` переименована в `invocations` и инкрементируется **после**
   проверки флага (вместо пре-инкремента внутри условия троттлинга).
3. Лог-сообщение `counter=%d` заменено на `invocation=%d`.

Вендорный код whisper.cpp **не изменялся**. Изменён только `whisper_jni.cpp`.

### 11.3. Измеренные задержки отмены

| Прогон | `stopAfterFlagMs` | Наблюдаемый код возврата `whisper_full` | Наблюдение | Результат |
|--------|-------------------|----------------------------|------------|-----------|
| 1 | 4899 мс | `-6` | `invocation=0` | PASS |
| 2 | 5328 мс | `-6` | `invocation=0` | PASS |
| 3 | 4888 мс | `-6` | `invocation=0` | PASS |

Диапазон: **4888–5328 мс**. Все три прогона ниже порога **10 000 мс**.

Замечание по коду `-6`: это **наблюдаемый** результат всех трёх прогонов отмены, а не
универсальный «код отмены». В закреплённом источнике `whisper.cpp` значение `-6`
возвращается из `whisper_full` при неудаче `whisper_encode_internal`
(`src/whisper.cpp:4179` и `src/whisper.cpp:7217`); энкодер прерывается, когда
`abort_callback` возвращает `true`. Публичная таблица кодов возврата в `whisper.h`
отсутствует, поэтому `-6` трактуется как наблюдаемое следствие срабатывания
`abort_callback`, а не как формально определённый код.

Сравнение с версией с троттлингом:

| Версия | Диапазон | Результат |
|--------|----------|-----------|
| С троттлингом (mod-8) | 9920 мс (PASS); ранее 15721 мс (FAIL) | нестабильно |
| Без троттлинга | 4888–5328 мс (3/3 PASS) | стабильно |

### 11.8. Ограничения и непроверенное

- Все измерения — x86_64-эмулятор. На реальном arm64-устройстве задержки будут
  другими. Физический телефон **не тестировался**.
- Задержка ~5 с определяется длительностью одного `ggml_graph_compute` (encode) на
  x86_64-эмуляторе. Callback вызывается один раз после завершения encode-графа, а не
  внутри него. Уменьшить задержку без изменения вендорного whisper.cpp невозможно.
- `invocation=0` означает, что флаг `true` был замечен на первом вызове callback,
  в котором он оказался `true`. До этого callback мог вызываться с результатом
  `false`. Точное количество предыдущих вызовов не логгируется.
- Код возврата `-6` — наблюдаемое значение (такой публичный идентификатор, как
  `WHISPER_FULL_ERROR_ENCODE`, в закреплённом `whisper.h` отсутствует); в закреплённом
  `whisper.cpp` `-6` возвращается при сбое encode. Из одного кода возврата нельзя с
  абсолютной точностью утверждать, что callback вызвался именно после encode-графа и не
  после чего-то ещё, возвращающего тот же код.
- Время установки флага измерено в Kotlin-домене (`System.nanoTime()`). Нативный
  `steady_clock` — другой домен. `stopAfterFlagMs` — согласованная метрика
  (Kotlin → Kotlin), но не совпадает с нативным `total_ms` из-за различия доменов.
- Три прогона на одном эмуляторе не гарантируют воспроизводимость на другом
  устройстве или после обновления whisper.cpp.
