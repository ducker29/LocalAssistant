# План и границы проекта

## Подтверждённые требования
- Android, Kotlin, Jetpack Compose.
- Локальный Qwen3-1.7B в GGUF Q4_K_M или Q4_0. Окончательный файл и совместимость runtime проверяются отдельно.
- Голосовой ввод с локальной транскрибацией; кандидат runtime — whisper.cpp.
- Локальная база знаний с поиском и сохранением заметок.
- Чтение календаря и запись после подтверждения пользователя.
- OpenCode CLI запускается из корня проекта в терминале Android Studio.

## Не определено
Модель телефона, RAM, версия ОС, minSdk, package name, точные версии библиотек, embedding-модель, размер базы, финальная Whisper-модель. Не выдумывать значения: сверить с проектом и пользователем.

## Последовательность
- [ ] M0: аудит существующего проекта; чистая сборка, тесты и lint.
- [ ] M1: минимальный UI чата и контракт движка с тестовым backend.
- [ ] M2: импорт GGUF, локальный llama.cpp-runtime, один запрос, отмена и освобождение ресурсов.
- [ ] M3: запись аудио, whisper.cpp, транскрипция, редактирование текста перед отправкой.
- [ ] M4: локальные заметки: добавление, чтение, изменение и удаление через UI.
- [ ] M5: retrieval: выбор embedding/search, индексация, ссылки на исходные фрагменты, ответ при отсутствии данных.
- [ ] M6: чтение календаря с runtime-разрешениями и корректной обработкой времени.
- [ ] M7: структурированные команды LLM, валидация и подтверждение записи в календарь/базу.
- [ ] M8: измерение RAM и задержек на телефоне, ошибки, отмена, офлайн-проверка и регрессионные тесты.

Это дорожная карта, не разрешение на реализацию всех этапов. Перед каждым этапом согласовать критерии приёмки. Тесты и privacy-проверки добавлять по мере реализации, не откладывать до M8.
